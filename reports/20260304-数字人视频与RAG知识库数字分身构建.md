## 1. 项目概况

### 1.1 研究背景与目标

本次研究聚焦于利用开源技术构建**个人数字分身（Digital Avatar）**，实现以下三大核心场景：

| 场景 | 描述 |
|------|------|
| **RAG知识库问答** | 将个人文章、笔记、演讲稿注入向量数据库，数字人以自己的风格回答问题 |
| **文章读写** | 数字人以指定语气撰写文章，或朗读已有文章并生成视频 |
| **演讲培训** | 输入演讲稿/大纲，数字人自动生成演讲视频，支持多轮打磨 |

## 3. 深度研究：数字分身构建方案

> 核心问题：如何将以上技术栈整合，构建一个**能说话、懂知识、有个性**的数字分身？

### 3.1 形象采集方案

**最小可行方案**：10秒正面讲话视频
- 使用 **Duix.Avatar** 的声音克隆功能，上传视频后系统自动提取：
  1. 静音视频（形象载体）
  2. 参考音频（声音特征）
  3. 声纹文本（用于TTS对齐）

**高质量方案**：
- 录制 5-10 分钟自然讲话视频，用于 **EchoMimicV2** 或 **MuseTalk** 训练，获得更高保真度的口型匹配

**半身演讲效果**：推荐使用 **EchoMimicV2** + 单张正面照，直接生成半身演讲视频（CVPR 2025 效果）

---

### 3.2 RAG知识库构建方案

**知识来源**：

| 来源类型 | 格式 | 处理方式 |
|---------|------|---------|
| 个人文章/博客 | Markdown / Word | RAGFlow DeepDoc 解析 |
| 演讲稿 | PDF / TXT | 段落级分块 |
| 书籍摘录 | PDF | DeepDoc + 布局分析 |
| 聊天记录 | CSV（微信导出） | ChromaDB 向量化 |
| 课程/会议录音 | 音频 | ASR（FunASR）转文本后处理 |

**推荐的知识库架构**：

```
个人知识库
├── 文章库（文章标题 + 全文向量）
├── 演讲库（PPT大纲 + 演讲稿 + 关键观点）
├── 问答库（历史QA对）
└── 语料库（个性化语言风格样本）
```

**个性化风格迁移（关键）**：
```python
# System Prompt 示例（注入个人风格）
```

### 3.3 文章生成与演讲视频生成流程

**文章生成流程**：
```
用户输入主题/大纲
    │
    ↓
RAGFlow 检索相关文章（相似内容 + 参考资料）
    │
    ↓
LLM 以个人风格生成文章草稿
    │
    ↓
用户审阅/修改
    │
    ↓
（可选）数字人朗读生成视频
```

**演讲视频生成流程**：
```
输入演讲稿（文字）
    │
    ↓
TTS 合成语音（FishSpeech 声音克隆版本）
    │
    ↓
数字人口型驱动（Duix.Avatar API / MuseTalk）
    │
    ↓
视频合成 + 字幕叠加（FFmpeg）
    │
    ↓
输出最终演讲视频（MP4）
```

**完整代码示意**（Python，调用 Duix.Avatar API）：
```python
import requests
import uuid

def generate_speech_video(text: str, voice_ref_audio: str, avatar_video: str) -> str:
    """
    生成演讲视频
    text: 演讲文字内容
    voice_ref_audio: 参考音频路径（声音克隆样本）
    avatar_video: 数字人形象视频路径
    """
    task_code = str(uuid.uuid4())
    
    # Step 1: TTS 合成（声音克隆）
    tts_response = requests.post(
        "http://127.0.0.1:18180/v1/invoke",
        json={
            "speaker": task_code,
            "text": text,
            "format": "wav",
            "reference_audio": voice_ref_audio,
            # ... 其他固定参数
        }
    )
    audio_path = tts_response.json()["audio_url"]
    
    # Step 2: 视频合成（口型驱动）
    video_response = requests.post(
        "http://127.0.0.1:8383/easy/submit",
        json={
            "audio_url": audio_path,
            "video_url": avatar_video,
            "code": task_code,
            "chaofen": 0,
            "watermark_switch": 0,
            "pn": 1
        }
    )
    
    # Step 3: 轮询任务进度
    while True:
        status = requests.get(
            f"http://127.0.0.1:8383/easy/query?code={task_code}"
        ).json()
        if status["status"] == "complete":
            return status["video_url"]
        elif status["status"] == "failed":
            raise Exception("视频生成失败")
        time.sleep(2)
```

### 3.4 关键发现

1. **全离线首选 Duix.Avatar**：10秒视频起步，完全本地运行，保护隐私，开放 API 便于集成，支持 Windows/Ubuntu 双平台。

2. **实时交互首选 LiveTalking**：已将 MuseTalk/Wav2Lip/ernerf 统一封装，支持 WebRTC 推流，适合直播/课程讲授场景，社区持续活跃（2026年仍更新）。

3. **高质量演讲推荐 EchoMimicV2**：蚂蚁集团出品，CVPR 2025 录用，单张照片驱动半身动画，9倍加速推理，适合录播演讲视频。

4. **RAG 引擎首选 RAGFlow**：70,000+ Stars，深度文档解析（DeepDoc），对中文支持极好，Agent 框架内置，企业级可靠性。

5. **个性化是核心难点**：数字分身的"灵魂"在于 RAG 知识库的质量 + Prompt 工程，建议从最小可行知识库（50-100篇文章）开始，逐步扩充。

## 4. 问题与不足

| 问题 | 影响程度 | 说明 |
|------|---------|------|
| **硬件门槛高** | 高 | Duix.Avatar 需 RTX 4070+，EchoMimicV2 需 A100/4090，个人用户负担较重 |
| **知识更新滞后** | 中 | RAG 知识库为静态索引，需定期更新，否则回答会过时 |
| **风格一致性** | 中 | 大模型生成内容难以百分百模拟个人语气风格，需大量 Few-shot 样本 |
| **实时性与质量的权衡** | 中 | 实时模式（LiveTalking）口型质量略低于离线 Duix.Avatar |
| **半身以下动作缺失** | 低 | EchoMimic/MuseTalk 只有面部/上半身，无肢体语言动作 |
| **隐私安全** | 高 | 使用声音/形象克隆须注意合法合规，避免被滥用 |
| **中文文档质量参差** | 中 | RAG-Avatar-Dialogue-System 仅为研究原型，无法直接用于生产环境 |
